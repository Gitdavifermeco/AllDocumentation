                                While and for

🌀 while se utiliza cuando:
No sabes cuántas veces se repetirá el bucle.

La repetición depende de una condición que cambia durante la ejecución (como lo que escribe el usuario, una conexión, o un estado).

Ideal cuando la condición de salida es incierta o depende del exterior.

Ejemplo típico:
Seguir preguntando hasta que el usuario diga "salir".

🔁 for se utiliza cuando:
Sí sabes cuántas veces quieres repetir algo.

Tienes una estructura clara: inicio, condición, y paso.

Ideal para recorrer arreglos, contar cosas, o repetir procesos fijos.

Ejemplo típico:
Imprimir los números del 1 al 10, recorrer un arreglo de nombres.

✅ Resumen corto:

Usa for cuando la cantidad de repeticiones ya está en el código.

Usa while cuando el bucle depende de lo que pase mientras se ejecuta.

                        Scanner

Qué significa Scanner sc = new Scanner(System.in);

    Esto crea un objeto Scanner llamado sc que está leyendo datos desde el teclado. Vamos a descomponerlo:

    Scanner → el tipo de objeto.

    sc → el nombre del objeto (puede ser cualquier nombre).

    new Scanner(System.in) → crea un nuevo objeto que escucha lo que el usuario escribe en la consola.

✅ Ejemplo básico:
    import java.util.Scanner;

    public class Main {
        public static void main(String[] args) {
            Scanner sc = new Scanner(System.in);  // Creamos el objeto Scanner

            System.out.print("Ingresa tu nombre: ");
            String nombre = sc.nextLine();  // Lee una línea completa

            System.out.print("Ingresa tu edad: ");
            int edad = sc.nextInt();  // Lee un número entero

            System.out.println("Hola " + nombre + ", tienes " + edad + " años.");
    }
}

next()	Lee una palabra
nextLine()	Lee una línea completa (incluye espacios)
nextInt()	Lee un número entero
nextDouble()	Lee un número decimal
hasNext()	Verifica si hay otro token disponible

🧠 Resumen de Getters y Setters explicado "a tu manera"
🧩 1. ¿Qué es un setter (setX)?
Es un método que te permite pasarle un valor nuevo a la variable privada (como x), y guardarlo en ella.

🔹 Tú lo entendiste así:

“Se crea un valor temporal (el parámetro x) que tiene el mismo nombre que la variable privada.
Luego haces this.x = x, y ese valor temporal se copia dentro del objeto.”

✔ Esa copia cambia el valor interno real del objeto.

🧩 2. ¿Qué es un getter (getX)?
Es un método que te devuelve el valor actual que tiene la variable privada.

🔹 Como tú dijiste:

“El getter saca el valor que tenga la variable en ese momento, ya sea el valor por defecto o el que tú pusiste antes con un setter.”

🧩 3. ¿Cómo funciona this.x = x?
El primer x → this.x → es el atributo del objeto, el verdadero que vive siempre.

El segundo x → es el parámetro temporal, que solo existe cuando llamas al método.

🔹 Como tú dijiste:

“Cada vez que llamas al setter, se crea una nueva copia temporal (x), se mete dentro de this.x, y luego esa temporal desaparece.”

✔ Pero el valor queda guardado dentro del objeto.

🧩 4. ¿Qué pasa si usas getX() antes de usar setX()?
🔹 Tú pensaste:

“¿Y si llamo a getX() antes de meter un valor con setX()?”

✔ Entonces te devuelve el valor por defecto:

int → 0

String → null

¿Por qué? Porque ese atributo (this.x) ya existe, pero nadie le ha puesto aún un nuevo valor.

🧩 5. ¿Entonces los setters y getters para qué sirven?
🔹 Tú lo entendiste así (y bien):

“Son como la forma que tiene el objeto de proteger sus variables internas.
Tú no puedes tocarlas directamente, pero puedes pedirle al objeto que te las dé o las cambie.”

✔ Es una forma segura y controlada de usar los datos del objeto sin romperlo.

🧠 Frase tuya resumida y corregida:
“El parámetro se crea cada vez que llamas al setter.
Al principio es igual que el atributo, pero lo puedes cambiar.
Cuando haces this.x = x, el valor se copia al atributo real,
y ese valor se mantiene mientras no lo vuelvas a cambiar.”

💯 ¡Exactamente así funciona!
